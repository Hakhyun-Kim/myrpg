# giwa-village 검토 — 블록체인 필요성 판정 + 재사용 요소

> 작성일 2026-07-31 · 대상: D:\giwa-village (GIWA 체인 해커톤, 한옥 저잣거리 3D 소셜 플랫폼)

## 1. 결론 먼저

**MyRPG에 블록체인은 넣지 않는다.** 근거는 4가지이고, 대신 **블록체인과 무관한 자산이 훨씬 많다** — 검증 문화, 밸런스 봇, Colyseus 서버 골격, 오디오/게임필 규율, 그리고 개발일지 패턴 자체.

## 2. 블록체인 판정 상세

### 2.1 왜 giwa-village에서는 맞는 선택이었나

giwa-village는 "지갑을 공간으로" 만드는 **소셜 플랫폼**이다. 핵심 상호작용(노점 개설, 선물, 길드 가입)은 분당 1회 이하의 저빈도 트랜잭션이고, "서버 없이 멀티플레이"가 해커톤의 증명 포인트였다. 체인이 곧 서버라는 설계가 성립하는 조건이 갖춰져 있었다.

### 2.2 왜 MyRPG에서는 아닌가

| # | 근거 | 설명 |
|---|---|---|
| 1 | **상태 갱신 빈도가 다르다** | MMO는 이동 15~20Hz, 전투 판정 초당 수 회, 제작 큐 틱이 상시 돈다. 블록 타임(수 초)과 가스 모델로는 게임 루프를 얹을 수 없고, 결국 권위 서버가 필요하다. 서버가 있는 순간 체인은 이중 장부일 뿐이다. |
| 2 | **경제 튜닝 권한을 포기할 수 없다** | GDD의 심장은 Sink/Faucet 비율 관리다. 아이템·화폐가 온체인 자산이 되면 밸런스 패치(수율 너프, 내구도 조정)가 "남의 재산 몰수"가 되어 사실상 불가능해진다. 우리는 수치를 계속 흔들어야 하는 단계다. |
| 3 | **규제 — giwa-village 스스로가 증거** | giwa-village조차 "게임 플레이 보상은 소울바운드, 오더북 금지"를 절대 규칙으로 박아 게임이 아닌 소셜 플랫폼으로 포지셔닝했다. 국내에서 양도 가능한 온체인 보상 + 게임 = 등급분류 거부 사유다. MyRPG의 핵심이 바로 자유 시장(오더북)이므로 정면 충돌한다. |
| 4 | **동접 수십 명에 탈중앙 신뢰가 필요 없다** | 블록체인의 대가(지연·가스·UX 마찰)는 "운영자를 못 믿는 다수의 이해관계자"가 있을 때 지불할 가치가 있다. 우리 규모에서는 서버 DB + 공개 시세 API로 투명성 요구를 전부 충족한다. |

**단서:** 나중에 "시즌 기록의 영구 보존"이나 "명품 각인의 위조 불가 증명" 같은 *저빈도·기록성* 요구가 생기면 그때 읽기 전용 앵커링(주기적 해시 커밋)만 고려한다. 게임 루프에는 어떤 경우에도 넣지 않는다.

## 3. 재사용 요소 (블록체인 무관)

우선순위 순. ★ = Phase 1~2에서 바로 쓸 것.

### ★ A. "밸런스 수치는 한 곳 + 어긋나면 테스트가 깨진다" (CLAUDE.md §4)
수치가 사는 곳을 표로 선언하고, 복수 지점에 존재할 수밖에 없는 값은 테스트가 대조한다. MyRPG의 `부록 A 밸런스 상수`를 이 패턴으로 관리한다 — 상수 YAML이 원본, 서버/클라 코드는 생성 또는 임포트, `npm test`가 일치를 강제.

### ★ B. 봇 시뮬레이션 인프라 (`scripts/bots.mjs`, `merchant-bot.mjs`, `lib/haggle.mjs`)
- 상인 봇 + 손님 봇으로 시장을 돌리고, 하한선 로직을 순수 모듈로 분리해 봇과 테스트가 공유하는 구조.
- **"값은 LLM이 제안하고 하한선은 코드가 강제"** 패턴 — MyRPG의 NPC 가격 밴드·일일 납품 계약 봇에 그대로 이식 가능.
- GDD Phase 2의 "봇 20개 × 7일 경제 시뮬"의 출발 코드가 이미 있는 셈이다.
- "일일 봇 실주행을 콘텐츠로 승격"(§8 chronicle 설계)은 미구현이지만 아이디어 자체를 가져온다 → **일일 시장 시세 기록을 개발일지/게임 내 게시판 콘텐츠로**.

### ★ C. Colyseus 서버 골격 (`server/VillageRoom.ts`)
15Hz 위치 동기화 룸이 이미 돌아간다. MyRPG의 존(지역) 서버 = Colyseus Room 1개로 시작하면 Phase 1 이동/채팅이 바로 나온다. 데드레커닝 클라 코드(`presence` 소비부)도 참고 가치.

### ★ D. 검증 문화 — 5겹 테스트 구조
- `npm test` 1초 미만 로직 테스트(저장할 때마다) / 스모크는 실브라우저로.
- **빈 localStorage(첫 방문자)로 여는 smoke:boot** — "처음 온 사람에게만 보이는 문제는 게이트가 없으면 조용히 망가진다."
- **PROTOCOL.md와 서버 소스를 테스트가 대조**하고, 문서만 보고 짠 클라이언트로 실제 입장해보는 protocol-smoke. MyRPG도 서버-클라 메시지 명세를 이 방식으로 지킨다.

### E. 절차 생성 오디오 (`client/src/audio/`)
tone()/noise() 두 원시 도구 + 단일 믹서 + 리버브 + 룩어헤드 스케줄러. "배경음은 한 곡이 아니라 상태다"(전투 근접 시 트랙 전환) 규율 포함. 에셋 예산이 0인 초기 단계에 배경음·효과음을 통째로 해결해 준다. 임계값을 순수 모듈로 빼서 테스트가 도는 구조까지 포함해 이식.

### F. 게임필 규율 (`game/feel.ts`)
매 프레임 값은 스토어에 넣지 않는다 / 새 오브젝트를 만들지 않고 기존 값을 흔든다 / 즉각 반응은 화면이, 사실 확인은 서버가 한다. 세 번째 규율은 MMO 네트워크 지연 은폐(클라 예측 + 서버 확정)와 정확히 같은 사상이라 전투 타격감 구현의 기준 문서로 삼는다.

### G. 에셋 원장 (`data/assets.json` + `npm run assets`)
출처·라이선스(CC0/CC-BY/OFL만)를 원장에 적고, 체크섬 대조 + 용량 예산을 테스트가 강제. 나중에 에셋을 반입하기 시작할 때 그대로 복사한다.

### H. 개발일지 + AI Self-Audit 패턴 (journal.html / audit.html)
"주장이 아니라 git 기록으로 되짚은" 일지, 개발한 AI가 감사자로 전환해 결함·미해결 한계까지 공개하는 감사 기록. **이번에 만드는 MyRPG 공개 개발일지의 직접 선례.**

### I. 온보딩 동선 규율
딱 한 번만 묻는다 / 빈손이어도 보여준다 / 안내는 겹치지 않는다. GDD §9.3(신규 진입)의 튜토리얼 구현 시 기준.

## 4. 가져오지 않는 것

| 요소 | 이유 |
|---|---|
| 컨트랙트 10종 전부 | §2 판정 |
| viem / 지갑 연결 / queueTx | 체인 전용. MyRPG 인증은 일반 계정(이메일/OAuth) |
| 소울바운드 보상 설계 | giwa는 규제 회피용이었다. MyRPG는 반대로 **모든 제작물이 양도 가능해야** 경제가 돈다 (서버 내 화폐 기준이므로 규제 문제 없음) |
| React Three Fiber 3D | MyRPG는 탑다운 2D. 렌더 스택은 새로 정한다 (Phaser/PixiJS 검토 예정) |
| "체인이 곧 서버다" 원칙 | MyRPG는 정반대 — **서버가 유일한 진실**이다 |

## 5. 실행 메모

- Phase 1 시작 시 B·C를 먼저 이식 (Colyseus 룸 + 봇 러너).
- A·D는 저장소 규칙(CLAUDE.md) 작성 시점에 반영.
- giwa-village 코드를 복사할 때는 파일 단위가 아니라 **모듈 단위로 발췌** — 체인 의존이 import 한 줄이라도 섞이면 안 가져온 것만 못하다.
